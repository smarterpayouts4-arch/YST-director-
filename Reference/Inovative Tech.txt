# Innovations Transfer Guide — Agent OS Patterns

Portable reference for recreating MarketMonth’s **agent / developer operating system** in another product. Copy this file into a new repo and treat MarketMonth paths below as a reference implementation.

## 0. Purpose and non-goals

### Purpose

Inventory the reusable innovations that make AI-assisted work reliable here:

- one layer for **what is true**
- one layer for **how agents work**
- one layer for **safe tool access**
- soft gates so maps stay fresh and claims stay honest

### Non-goals

Do **not** port MarketMonth product features as part of this guide:

- Discovery crawl / LEARN business pipeline
- Content Brain / Content Universe product loop
- Idea Lab product surfaces
- Brand / strategy doctrine content

### Hard separation (keep this invariant)

| Layer | Role | MarketMonth home |
|-------|------|------------------|
| **Project Knowledge** | What is true (canonical SoT) | `project-knowledge/` |
| **APS** | How agents work (routing, specs, evidence) | `agent-prompt-system/` |
| **Product MCP** | Allowlisted reads + domain ops | `mcp/` |
| **Helper MCP / research** | Advisory tooling (Playwright, Context7, …) | Docker profile / external MCP |
| **Product prompts** | Runtime LLM strings inside the app | e.g. `src/brain/**` — **not** APS |

```text
APS ≠ product prompts ≠ MCP ≠ Knowledge SoT
```

Never merge process docs into product doctrine. Never treat helper MCPs as source of truth.

---

## 1. Layered architecture

```mermaid
flowchart TB
  knowledge[project-knowledge Truth]
  mcp[Product_MCP Ops_and_reads]
  aps[APS How_agents_work]
  hooks[Cursor_hooks Soft_gates]
  aps --> knowledge
  mcp --> knowledge
  hooks --> aps
  hooks --> knowledge
```

**Cold start for agents:** `AGENTS.md` → knowledge README → `CURRENT_STATE` → task-specific canonical doc → only then MCP LEARN / code edits.

**Authority hierarchy (narrowest first):**

1. Canonical knowledge doc (or allowlisted MCP read of that doc)
2. Spanning Q&A over allowlisted excerpts (optional; only if a server is already running)
3. Sole docs index → direct file read (when Q&A unavailable)
4. Generated maps + source for live implementation detail
5. External web / research MCP (advisory only)

## 2. Innovation catalog

Maturity uses MarketMonth vocabulary: **Live** | **Partial** | **Experimental**.

For each item: **what**, **why transfer**, **key paths**, **maturity**, **strip when porting**.

### 2.1 Knowledge OS (docs-as-truth + generated maps)

| | |
|--|--|
| **What** | Canonical human/agent doctrine under a knowledge root; scripts write **only** under `generated/` (maps, indexes, reports). Doctrine is never auto-rewritten by scanners. |
| **Why** | Agents and humans share one reality layer; maps regenerate from code; stale doctrine is detectable. |
| **Key paths** | `project-knowledge/README.md`, `CURRENT_STATE.md`, `PRODUCT.md`, `ARCHITECTURE.md`, `FEATURES/`, `DECISIONS/`, `templates/`, `scripts/update.mjs`, `scripts/check.mjs`, `generated/maps/`, `generated/indexes/`, `generated/reports/` |
| **Maturity** | Live |
| **Strip** | MarketMonth product doctrine content; keep layout, frontmatter authority, update/check contract, templates. |

### 2.2 Sole docs-index + agent-bootstrap

| | |
|--|--|
| **What** | One authoritative `docs-index.json`. Cold-start `agent-bootstrap.json` lists required first reads, status vocabulary, and MCP tool names for docs access. |
| **Why** | Token-efficient cold start; no competing indexes. |
| **Key paths** | `project-knowledge/generated/indexes/docs-index.json`, `agent-bootstrap.json`, `manifest.json` |
| **Maturity** | Live |
| **Strip** | MM-specific doc ids; keep “one index + bootstrap pointers” pattern. |

### 2.3 CURRENT_STATE status vocabulary

| | |
|--|--|
| **What** | Strict statuses: Live / Partial / Prototype / Mocked / Planned / Blocked / Deprecated. Freshness: current / stale / historical / superseded. Hard-stop building on ghost features. |
| **Why** | Highest-ROI anti-hallucination pattern for partially shipped products. |
| **Key paths** | `project-knowledge/CURRENT_STATE.md`, `templates/CURRENT_STATE_AREA.md`, `docs/ai/agent-auditor-playbook.md` |
| **Maturity** | Live |
| **Strip** | Area rows that describe MM features; keep vocabulary + template. |

### 2.4 Agent Prompt System (APS)

| | |
|--|--|
| **What** | Portable Cursor task-routing kit: classify → ≤3 workflows → resolve `project-context/` **pointers** into canonical knowledge → task spec → evidence labels. Machine `manifest.json` + install/validate scripts. |
| **Why** | Designed to copy to a new repo (`onboard-new-project`). Core + workflows are portable; only pointer stubs are product-specific. |
| **Key paths** | `agent-prompt-system/README.md`, `SYSTEM.md`, `manifest.json`, `core/`, `workflows/`, `project-context/`, `templates/`, `scripts/install.mjs`, `validate.mjs`, `initialize-project-context.mjs` |
| **Maturity** | Live |
| **Strip** | MM-specific `required_context` extras; re-point stubs to the new product’s knowledge docs. |

### 2.5 Pointer stubs vs doctrine

| | |
|--|--|
| **What** | APS `project-context/` files are short pointers, not copies of PRODUCT/ARCHITECTURE. Agents must resolve and read the canonical file. |
| **Why** | Prevents forked SoT inside the process layer. |
| **Key paths** | `agent-prompt-system/project-context/` |
| **Maturity** | Live |
| **Strip** | Stub targets that name MM-only docs; keep the pointer rule. |

### 2.6 Cursor adapter: bridge rule + bootstrap + skill

| | |
|--|--|
| **What** | Adapters under `adapters/cursor/` are SoT. `install.mjs` copies into `.cursor/`; `validate.mjs` fails on drift. Do not hand-edit installed copies. |
| **Key paths** | `agent-prompt-system/adapters/cursor/agent-prompt-router.mdc`, `agent-bootstrap.mdc`, `skills/aps-router/SKILL.md`, installed `.cursor/rules/`, `.cursor/skills/aps-router/` |
| **Maturity** | Live |
| **Strip** | Product name in bridge text if desired; keep thin always-on bridge + on-demand skill. |

### 2.7 Soft-enforcement Cursor hooks

| | |
|--|--|
| **What** | Fail-open hooks: substantial-prompt heuristic → session marker → remind before Write/StrReplace → on stop run knowledge update/check for structural paths + evidence reminder. |
| **Why** | Mechanical compliance lift without hard-blocking the model. Honesty bound: packaging sync ≠ agent obedience. |
| **Key paths** | `agent-prompt-system/adapters/cursor/hooks.json`, `hooks/aps-before-submit.mjs`, `aps-pre-tool-use.mjs`, `aps-stop.mjs`, `hooks/lib/substantial-prompt.mjs`, `knowledge-structural.mjs` |
| **Maturity** | Live (soft) |
| **Strip** | Path lists that are MM-specific; keep fail-open + structural refresh pattern. |

### 2.8 APS brief + evidence-label contract

| | |
|--|--|
| **What** | User-visible opener `Selected workflows: …`. Completion labels: Verified / Partially verified / Not verified / Blocked / Assumed. |
| **Key paths** | `agent-prompt-system/core/verification-contract.md`, `core/spec-builder.md`, `templates/task-spec-template.md` |
| **Maturity** | Live (process); soft via hooks |
| **Strip** | Nothing material — fully portable. |

### 2.9 Repo-local stdio MCP (modular registration)

| | |
|--|--|
| **What** | Thin MCP server: register tool groups (context / domain / status). Cursor wires via gitignored `mcp.json` from a tracked example. |
| **Why** | Product MCP wraps ops without becoming doctrine. |
| **Key paths** | `mcp/src/create-server.ts`, `create-server/reg-context.ts`, `reg-discovery.ts`, `reg-seo.ts`, `stdio-server.ts`, `.cursor/mcp.json.example`, `docs/ai/mcp.md`, `mcp/README.md` |
| **Maturity** | Live (stdio); Docker catalog packaging Partial |
| **Strip** | `reg-discovery.ts` and MM LEARN tools; keep context tools + registrar pattern. |

### 2.10 Allowlisted document registry

| | |
|--|--|
| **What** | Tools accept **document IDs** only; arbitrary filesystem reads/writes of knowledge/src/APS trees forbidden. Unknown IDs → `DOCUMENT_NOT_REGISTERED` + alternatives. |
| **Key paths** | `mcp/src/security/docs-registry.ts`, `security/paths.ts`, `tools/context/read-doc.ts`, `list-docs.ts`, `find-doc.ts` |
| **Maturity** | Live |
| **Strip** | MM doc ids; keep ID→path registry + rejection semantics. |

### 2.11 Status envelopes + secret hygiene

| | |
|--|--|
| **What** | Uniform `complete | partial | failed` responses with warnings/uncertainty; stderr-only logging; SSRF / private IP policy for outbound URL tools. |
| **Key paths** | `mcp/src/contracts/envelope.ts`, `lib/log.ts`, `security/url-policy.ts` |
| **Maturity** | Live |
| **Strip** | Domain-specific URL allowlists; keep envelope + logging rules. |

### 2.12 MCP smoke suite + doctor + capability matrix

| | |
|--|--|
| **What** | Protocol/security tests spawn a fresh stdio server (not Cursor’s cached schema). Allowlist drift + nav drift tests. Doctor checks required tools + registry hash. Living capability matrix documents R/W scope and **non-capabilities**. |
| **Key paths** | `mcp/test/smoke.ts`, `test/smoke/allowlist-drift.ts`, `nav-drift.ts`, `security.ts`, `mcp/scripts/doctor.mjs`, `docs/ai/mcp-capability-matrix.md` |
| **Maturity** | Live |
| **Strip** | Discovery-tool matrix rows; keep drift tests for context registry. |

### 2.13 Guardian + ownership + dual quality scores

| | |
|--|--|
| **What** | Guardian emits `PK-HARD-*` (block closeout) and `PK-WARN-*` (acknowledge with reason). Ownership rules as JSON (UI≠engine, etc.). Dual scores: internal engineering rubric vs external baseline; `--fast` ≠ official; advisory AI audit cannot change score. |
| **Key paths** | `project-knowledge/scripts/guardian.mjs`, `guardian/hard.mjs`, `soft.mjs`, `codes.mjs`, `ownership-rules.json`, `quality-rules.json`, `QUALITY_RUBRIC.md`, `scripts/quality.mjs`, `generated/reports/STRUCTURE_WARNINGS.md` |
| **Maturity** | Live |
| **Strip** | MM path literals in ownership rules; keep code taxonomy + dual-score idea. |

| Keep pattern | Drop / replace |
|--------------|----------------|
| MCP context tools (list / find / read / bootstrap) | `mm_crawl_*`, brand/SEO/social/competitors/strategy LEARN wrappers |
| APS `core/` + most `workflows/` | Product-only required_context extras |

| Docker profile **shape** | YouTube-as-Content-Universe narrative |

## 4. Day-1 porting checklist

Ordered for a greenfield or existing product repo:

1. **Scaffold knowledge**
   - Create `project-knowledge/` (or rename) with README, PRODUCT, ARCHITECTURE, CURRENT_STATE, templates.
   - Create empty `generated/{maps,indexes,reports}/` and decide “scripts write only here.”

2. **Port update / check / guardian**
   - Adapt scanners to the new `src/` layout.
   - Wire `knowledge:update`, `knowledge:check`, `knowledge:guardian` (and optional `knowledge:sync` on predev/prebuild).
   - Define ownership-rules and guardian hard/soft codes for the new boundaries.

3. **Copy APS**
   - Copy `agent-prompt-system/` (core, workflows, adapters, scripts, templates).
   - Run `initialize-project-context.mjs` (or rewrite stubs) to point at the new knowledge docs.
   - Run `node agent-prompt-system/scripts/install.mjs` then `validate.mjs`.
   - Confirm `.cursor/rules/agent-prompt-router.mdc`, `agent-bootstrap.mdc`, skill, and hooks are installed from adapters (not hand-edited).

4. **Build allowlisted context MCP**
   - Keep registrar pattern + docs-registry + envelopes.
   - Register context tools first; add domain ops later behind the same security wrappers.
   - Track `.cursor/mcp.json.example`; gitignore live `mcp.json`.
   - Add smoke tests for allowlist drift + `mcp:doctor`.

5. **Wire npm scripts + CI**
   - Minimum: `knowledge:check`, APS `validate.mjs`, `mcp:test` (or doctor), cursor-context validate.
   - Document authority hierarchy in root `AGENTS.md`.

6. **Verify**
   ```bash
   node agent-prompt-system/scripts/validate.mjs
   npm run knowledge:check
   npm run mcp:test
   npm run mcp:doctor
   npm run validate:cursor-context
   ```

Suggested priority: **P0** Knowledge OS + CURRENT_STATE + APS → **P1** MCP context allowlist + guardian/ownership + indexing policy → **P2** Docker helpers / ask API → **P3** personas.

---

## 5. Anti-patterns

- Treating **packaging sync** (`validate.mjs`) as proof of **agent compliance**
- Hand-editing `generated/` maps or installed `.cursor` APS copies (edit adapters → reinstall)
- Letting MCP **write** doctrine or orchestrate whole product workflows
- Merging APS into app runtime / product prompt modules
- Starting the whole app merely to answer a docs question
- Letting research vaults / RepoBrain / reference libraries override PRODUCT / ARCHITECTURE / CURRENT_STATE
- Inventing MCP capabilities not listed in the capability matrix
- Treating `quality:update --fast` as the official quality score

### 6.3 MCP tools — keep vs strip

**Port first (context / cold-start):**

| Tool | Role |
|------|------|
| `mm_get_agent_bootstrap` | Cold-start pointers |
| `mm_list_project_docs` | Allowlisted doc catalog |
| `mm_find_project_doc` | Query → candidate ids |
| `mm_read_project_doc` | Read by id |
| `mm_product_overview` | Parse PRODUCT |
| `mm_architecture_map` | Parse ARCHITECTURE |
| `mm_route_inventory` | Live app routes |
| `mm_stage_for_request` | Stage recommendation (guide, not authority) |

**Strip or replace with your domain ops:**

| Tool | Role |
|------|------|
| `mm_crawl_website` | Bounded crawl |
| `mm_extract_brand` | Brand signals |
| `mm_analyze_seo` | Customer-site SEO |
| `mm_discover_social` | Social links |
| `mm_suggest_competitors` | Competitor hints |
| `mm_draft_strategy` | Strategy draft (human review) |
| `mm_analyze_website` | Full analyze pipeline |
| `mm_seo_status` | Product-site SEO status |

Rename the `mm_` prefix to your product when porting; keep the **context vs domain-ops** split.

## Honesty bound

This guide describes patterns that are **Live** in MarketMonth’s docs and trees. Soft hooks and advisory rules raise compliance; they do not create mathematical certainty that every agent turn followed APS. Prefer evidence labels over “100% transferred.”
