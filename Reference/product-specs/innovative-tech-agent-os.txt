# Innovations Transfer Guide — Agent OS Patterns

Portable blueprint for recreating this repo’s **agent / developer operating system** and **AI Control** patterns in another product. Copy this file into a new repo and treat **Research Prompt Builder (RPB)** paths below as the reference implementation.

**Origin:** patterns distilled from MarketMonth’s Agent OS, then hardened in RPB (AI Control freeze + Living Architecture Guardian P0). MarketMonth product features are not part of this guide.

For mechanism deep-dives, use [`docs/portability/AI_ENGINEERING_FOUNDATIONS_PLAYBOOK.md`](../../docs/portability/AI_ENGINEERING_FOUNDATIONS_PLAYBOOK.md).

## 0. Purpose and non-goals

### Purpose

Inventory the reusable innovations that make AI-assisted product work reliable:

- one layer for **what is true** (Project Knowledge)
- one layer for **how agents work** (APS)
- one layer for **safe tool access** (read-only product MCP)
- one plane for **how the product calls models** (AI Control)
- soft gates so maps stay fresh and claims stay honest
- **constitution tests** so existence of a registry/map is not mistaken for legitimacy

### Non-goals

Do **not** port host-product features as “foundation”:

- Research execution, topics, scripts, video pipelines
- Auth / multi-user / DB / CMS as MVP defaults
- Write MCP, filesystem/shell MCP as product intelligence
- Auto-rewriting `AGENTS.md` or canonical doctrine
- LangChain / orchestration buses / prompt CMS
- CI-blocking LLM “architecture auditors” as source of truth

### Hard separation (keep this invariant)

| Layer | Role | RPB home |
|-------|------|----------|
| **Project Knowledge** | What is true (canonical SoT) | `project-knowledge/` |
| **APS** | How agents work (routing, IntentContract, evidence) | `agent-prompt-system/` |
| **Product MCP** | Allowlisted read-only project intelligence | `mcp/` (`rpb_*`) |
| **Helper MCP / research** | Advisory tooling (Context7, Playwright, …) | Cursor profile / external — never product SoT |
| **AI Control / product prompts** | Runtime LLM ops, schemas, compilers, traces | `src/ai/**`, feature `prompts/`, `schemas/`, `services/` — **not** APS |

```text
Project Knowledge ≠ APS ≠ Product MCP ≠ Runtime Product Prompts
```

AI Control is a **product runtime plane**, not a process docs folder. Never merge APS into app prompts. Never treat helper MCPs or generated maps as doctrine.

## 1. Layered architecture

```mermaid
flowchart TB
  product["Product plane UI state export"]
  aiControl["AI Control ops prompts schemas"]
  knowledge["Project Knowledge canon"]
  generated["generated maps inventory"]
  constitution["constitution tests authority"]
  aps["APS process routing"]
  mcp["RPB MCP read-only"]
  product --> aiControl
  knowledge --> generated
  constitution -->|"verifies"| aiControl
  generated -.->|"derived only"| mcp
  aps --> knowledge
  mcp --> knowledge
```

**Cold start for agents:** `AGENTS.md` → `project-knowledge/README.md` → `CURRENT_STATE.md` → task-specific canonical doc → only then MCP / code edits. Prefer `rpb_get_agent_bootstrap` when MCP is available.

**Authority hierarchy (narrowest first):**

1. Canonical knowledge doc (or allowlisted MCP read of that doc)
2. Executable AI Control: `src/ai/operations/registry.ts` + `tests/ai/operations-registry.test.ts` (for ops truth)
3. Sole docs index → direct file read (when MCP unavailable)
4. Generated maps + doctor inventory (**derived navigation only**)
5. README operation tables (**pointers**, not a second registry)
6. External web / research MCP (advisory only)

**Living Architecture Guardian lesson:** scaffold scanners and `knowledge:update` maps can look green while unused registries, dead `*-policy` twins, phantom op ids, and generated inventories compete as truths — because they checked **existence**, not **authority relationships**. Constitution tests close that gap for AI Control. See `project-knowledge/TOOLING.md`.

## 2. Innovation catalog

Maturity vocabulary: **Live** | **Partial** | **Experimental** | **Planned**.

For each item: **what**, **why transfer**, **key paths**, **maturity**, **strip when porting**.

### 2.1 Knowledge OS (docs-as-truth + generated maps)

| | |
|--|--|
| **What** | Canonical human/agent doctrine under a knowledge root; scripts write **only** under `generated/` (maps, indexes, reports). Doctrine is never auto-rewritten by scanners. |
| **Why** | Agents and humans share one reality layer; maps regenerate from code. |
| **Key paths** | `project-knowledge/README.md`, `CURRENT_STATE.md`, `PRODUCT.md`, `ARCHITECTURE.md`, `PROMPT_CONTRACT.md`, `TOOLING.md`, `DECISIONS/`, `scripts/update.mjs`, `scripts/check.mjs`, `generated/` |
| **Maturity** | Live |
| **Strip** | Host product doctrine content; keep layout, update/check contract, generated-only write boundary. |

### 2.2 Sole docs-index + agent-bootstrap

| | |
|--|--|
| **What** | One authoritative `docs-index.json`. Cold-start `agent-bootstrap.json` lists required first reads, status vocabulary, and MCP tool names. |
| **Why** | Token-efficient cold start; no competing indexes. |
| **Key paths** | `project-knowledge/generated/indexes/docs-index.json`, `agent-bootstrap.json`, `project-knowledge/manifest.json` |
| **Maturity** | Live |
| **Strip** | Product-specific doc ids; keep “one index + bootstrap pointers.” |

### 2.3 CURRENT_STATE status vocabulary

| | |
|--|--|
| **What** | Strict statuses: Live / Partial / Prototype / Mocked / Planned / Blocked / Deprecated. Treat literally. |
| **Why** | Highest-ROI anti-hallucination pattern for partially shipped products. |
| **Key paths** | `project-knowledge/CURRENT_STATE.md` |
| **Maturity** | Live |
| **Strip** | Feature rows; keep vocabulary + honesty discipline. |

### 2.4 Agent Prompt System (APS)

| | |
|--|--|
| **What** | Portable Cursor intent compiler: classify → ≤3 workflows → resolve `project-context/` **pointers** → IntentContract → evidence labels. Machine `manifest.json` + install/validate. |
| **Why** | Process layer stays portable; only pointer stubs are product-specific. |
| **Key paths** | `agent-prompt-system/README.md`, `manifest.json`, `core/`, `workflows/`, `project-context/`, `scripts/install.mjs`, `validate.mjs` |
| **Maturity** | Live packaging / Partial compile fidelity (soft enforce; Gate C hooks Planned) |
| **Strip** | Product-only `required_context`; re-point stubs. |

### 2.17 Three-plane separation

| | |
|--|--|
| **What** | **Product** (UI, state, export) · **AI Control** (prompts, schemas, ops, traces) · **Engineering Intelligence** (knowledge, APS, MCP, learning). ADR in knowledge. |
| **Why** | Stops process docs, runtime prompts, and doctrine from collapsing into one mush. |
| **Key paths** | `AGENTS.md`, `project-knowledge/ARCHITECTURE.md`, `project-knowledge/DECISIONS/0001-three-plane-separation.md` |
| **Maturity** | Live |
| **Strip** | Product nouns; keep the three-plane invariant. |

### 2.18 AI operation registry + typed identity

| | |
|--|--|
| **What** | Single `operationRegistry`; `AiOperationId = keyof typeof operationRegistry`. Public ops declare `promptModulePath`, `schemaName`, `evalPath`. Nested repair is visibility=`nested` with `schemaName: null`. |
| **Why** | Phantom op ids and dual taxonomies die at the type boundary. |
| **Key paths** | `src/ai/operations/registry.ts`, `schema-names.ts`, `src/ai/README.md` |
| **Maturity** | Live |
| **Strip** | Op list; keep typed identity + public/nested split. |
| **Honesty** | Services may pass **typed literals**; `getOperation()` need not be a runtime orchestration bus. Declare-site + constitution is enough for MVP. |

### 2.19 AI Control constitution tests

| | |
|--|--|
| **What** | Vitest suite verifies relationships: public op ↔ prompt file ↔ schemaName ↔ eval ↔ repair policy; README mentions public ids; unknown ids rejected; generated `runtime-prompts.json` `versionLiteral` for `prompt-version.ts` matches `RUNTIME_PROMPT_VERSION`; `src/config/*-policy.ts` allowlist = `upload-policy.ts` only. |
| **Why** | This is the fix for “green inventory, wrong architecture.” |
| **Key paths** | `tests/ai/operations-registry.test.ts`, `project-knowledge/TOOLING.md` |
| **Maturity** | Live (in `npm test` / `verify`) |
| **Strip** | Product paths; keep relationship matrix idea. |

### 2.20 Repair policy by schemaName

| | |
|--|--|
| **What** | `getRepairPolicy(schemaName)` sets maxAttempts (e.g. ≤1 default, ≤2 for final compile). Null/missing structured parse is **not** repaired. Repair prompt is fenced instruction, not a second product SoT. |
| **Why** | Highest-ROI structured-LLM reliability without opaque retry loops. |
| **Key paths** | `src/ai/operations/repair-policy.ts`, feature `prompts/repair-output.ts`, `structured-openai` service |
| **Maturity** | Live |
| **Strip** | Schema names; keep policy table + null-parse rule. |

### 2.21 Context compilers + decision ledger + AiTrace

| | |
|--|--|
| **What** | Per-op context assemblers with budgets + deep redact. Decision ledger rebuild-on-read (not a second persisted SoT). AiTrace: typed `operationId`, versions, hashes, latency, `repairAttempts`, `finalValidation` — no prompt bodies/PII. |
| **Key paths** | `src/ai/context/`, `src/ai/traces/`, brief/prompt assemblers |
| **Maturity** | Live |
| **Strip** | Domain fields; keep compiler + ledger + trace shapes. |

### 2.22 Single invariant owners

| | |
|--|--|
| **What** | Business gates that matter (e.g. interview → brief) have **one** deterministic function enforced on the **server**, shared by UI for UX only. Example: `canCompleteInterview` on next-question **and** brief build. |
| **Why** | Stops LLM/UI/API bypass paths from disagreeing. |
| **Key paths** | `src/features/.../lib/can-complete-interview.ts`, auth-boundary tests under `tests/services/` |
| **Maturity** | Live |
| **Strip** | Domain categories; keep “one owner, server enforces.” |

### 2.23 Deterministic export lint / evals

| | |
|--|--|
| **What** | Merge-gate quality via deterministic contract lint + offline eval fixtures — not live-LLM judges in CI. |
| **Why** | Repeatability without flaky model spend. |
| **Key paths** | feature `validation/`, `tests/evals/`, Prompt Contract docs |
| **Maturity** | Live |
| **Strip** | Domain rules; keep “deterministic gate + offline fixtures” pattern. |

### 2.24 Doctor → verify ladder

| | |
|--|--|
| **What** | `doctor` = human-facing scaffold + light wiring checks. `verify` = doctor + lint + typecheck + test (incl. constitution) + knowledge + APS + MCP + build + E2E. Doctor does **not** duplicate the full AI relationship matrix. |
| **Key paths** | `scripts/doctor.mjs`, `package.json` scripts, `project-knowledge/TOOLING.md` |
| **Maturity** | Live |
| **Strip** | Host checks; keep ladder separation (scaffold vs constitution). |

## 3. Keep vs strip (quick matrix)

| Keep pattern | Drop / replace |
|--------------|----------------|
| MCP context tools (`rpb_*` / rename prefix) | Crawl/SEO/LEARN tool farms, write MCP |
| APS `core/` + lean workflows | Bloated product-only workflow kits claimed as universal |
| Knowledge scripts + Guardian HARD/WARN | Unread decorative JSON “rules,” dual score theaters |
| Typed op registry + constitution tests | Parallel model-policy modules; registry-as-orchestration-bus |
| Repair policy by schemaName | Opaque infinite repair; repair prompt as product SoT |
| Single server invariant owners | Multi-path completion (UI vs API vs LLM disagree) |
| Status + freshness vocabulary | Ghost “Live” rows without code |
| Doctor scaffold + verify ladder | Doctor that pretends to be semantic architecture proof |
| Evidence labels | “100% transferred” claims |

## 4. Day-1 porting checklist

Ordered for a greenfield or existing product repo:

1. **Scaffold knowledge**
   - `project-knowledge/` with README, PRODUCT, ARCHITECTURE, CURRENT_STATE, TOOLING.
   - Empty `generated/{maps,indexes,reports}/`; scripts write only here.

2. **Cold-start**
   - Root `AGENTS.md` with planes + evidence labels + cold-start order.
   - Bootstrap JSON after first `knowledge:update`.

3. **Lean APS**
   - Copy `agent-prompt-system/` core + workflows + adapters.
   - Point `project-context/` stubs at new knowledge docs.
   - `install.mjs` then `validate.mjs`. Do not hand-edit `.cursor` copies.

4. **Read-only product MCP**
   - Registrar + docs-registry + envelopes + allowlist-drift + doctor.
   - Track `mcp.json.example`; gitignore live `mcp.json`.
   - Owner lockdown: disable write/filesystem/shell MCP for the workspace.

5. **AI Control before the second LLM call**
   - Contract registry + operation registry with typed ids.
   - Constitution tests for op ↔ prompt ↔ schema ↔ eval ↔ repair.
   - Context compilers + redact/budgets + repair policy + AiTrace.
   - One server-owned invariant for any critical transition.
   - **Do not** wire `getOperation()` as an orchestration bus unless a real need appears.

6. **Guardian + doctor + verify**
   - HARD codes for generated markers / dangerous crossings.
   - Doctor for scaffold; vitest for relationships.
   - CI runs the verify umbrella.

7. **Verify**
   ```bash
   npm run doctor
   npm run test
   npm run knowledge:update
   npm run knowledge:check
   npm run knowledge:guardian
   npm run agent:validate
   npm run mcp:test
   npm run mcp:doctor
   npm run verify
   ```

Suggested priority: **P0** Knowledge + CURRENT_STATE + AGENTS + lean APS → **P1** read-only MCP + owner lockdown → **P2** AI Control registry + constitution + repair → **P3** Guardian HARD + doctor/verify → **later** soft hooks / learning / advisory audits.

## 5. Anti-patterns

- Treating **packaging sync** (`agent:validate`) as proof of **agent compliance**
- Hand-editing `generated/` maps or installed `.cursor` APS copies
- Letting MCP **write** doctrine or orchestrate product workflows
- Merging APS into app runtime / product prompt modules
- Letting research vaults / RepoBrain / Reference override PRODUCT / ARCHITECTURE / CURRENT_STATE
- **Existence of a registry, map, or `*-policy.ts` file ≠ legitimacy**
- Decorative JSON that looks like policy but is never executed
- Competing `src/config/*-policy.ts` twins (keep a single real SoT; RPB: upload-policy only)
- Phantom operation ids in traces / APIs
- Multiple completion gates (UI vs API vs LLM) for the same invariant
- Treating `runtime-prompts.json` or README tables as a second ops registry
- CI-blocking LLM architecture auditors as SoT
- Claiming APS IDE hard hooks exist when only soft/Planned
- Using Context7 (or any docs/web MCP) as product truth

## Honesty bound

This guide describes patterns that are **Live or Partial** in RPB with evidence labels. Soft APS routing and owner MCP lockdown raise compliance; they do not create mathematical certainty that every agent turn followed process. Prefer evidence labels over “100% transferred.” Product truth remains `project-knowledge/`; this file is **supporting** authority only.
